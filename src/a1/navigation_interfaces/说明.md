# a1_navigation_interfaces 说明

`a1_navigation_interfaces` 是 A1 上层模块之间的自定义通信协议包。

这个包只放 ROS 的 `msg`、`srv`、`action` 接口定义，不放节点、不写算法、不直接发布或订阅 topic。它的作用是让 `floor_mapping`、`exploration`、`mission_manager`、`danger_perception`、`result_manager`、`cmd_mux`、`building_behavior` 等模块用统一的数据格式通信。

原则：

```text
能用标准 ROS 类型就不要自定义。
```

例如：

```text
二维地图：nav_msgs/OccupancyGrid
里程计：nav_msgs/Odometry
目标点：geometry_msgs/PoseStamped
速度：geometry_msgs/Twist
点云：sensor_msgs/PointCloud2
普通导航 action：move_base_msgs/MoveBaseAction
简单触发服务：std_srvs/Trigger
模块诊断：diagnostic_msgs/DiagnosticStatus / DiagnosticArray
```

本包只定义 A1 任务里标准 ROS 类型表达不清的业务语义，比如楼层状态、任务状态、危险源检测/融合结果、速度仲裁状态、探索任务和特殊建筑行为。

## 跨模块接口管理规则

- 任何需要暴露给其他模块的项目自定义 `msg`、`srv` 或 `action`，统一在
  `a1_navigation_interfaces` 中定义；业务包只依赖和使用接口，不得在各自包中复制一份近似定义。
- 已有标准 ROS 接口能够完整表达语义时直接复用，例如 `nav_msgs/OccupancyGrid`、
  `geometry_msgs/Twist` 和 `move_base_msgs/MoveBaseAction`，不要为了“统一放置”而重复封装。
- 新增或修改共享接口前，必须先明确发布者、消费者、topic/service/action 名称、字段单位、
  `frame_id`、时间戳、有效/失败状态和生命周期；涉及已有字段时还要说明兼容策略。
- 共享接口改动应作为独立审查项通知相关模块负责人。接口合入后，各业务模块再分别接入，
  避免某个模块私自修改协议导致其他同学同时失效。
- 仅供包内部使用且不会被其他模块依赖的数据结构留在业务包内部，不进入本接口包。

这条规则约束的是跨模块协议的归属和评审流程，不要求把所有 ROS topic 都改造成自定义消息。

## msg

`msg` 一般用于 topic，表示某个模块持续发布的状态或结果。

### CmdMuxStatus.msg

发布者：

```text
a1_cmd_mux
```

典型 topic：

```bash
/a1/cmd_mux/status
```

作用：

```text
表示当前最终 /cmd_vel 由谁控制，以及速度仲裁器是否处于急停、禁用或正常输出状态。
```

订阅者可能包括：

```text
a1_mission_manager
a1_bringup
测试脚本
UI / 日志工具
```

注意：速度命令本身仍然使用标准 `geometry_msgs/Twist`，例如：

```bash
/cmd_vel_nav
/cmd_vel_behavior
/cmd_vel_teleop
/cmd_vel
```

`CmdMuxStatus.msg` 只汇报仲裁状态，不替代速度消息。

### DangerDetection.msg

发布者：

```text
a1_danger_perception
```

作用：

```text
表示感知模块在某一帧中观测到的一个危险源候选或危险源目标。
```

它是单次观测结果，强调“这一帧我看到了什么”。

典型字段含义：

```text
header.frame_id  位置所在坐标系
position         危险源三维位置，单位 meter
confidence       置信度，0.0 到 1.0
class_name       类别，例如 danger_red_sphere
track_id         感知模块内部跟踪 ID
is_valid         是否可供 result_manager / mission_manager 使用
status           状态，例如 ok、tracked、tf_unavailable、insufficient_valid_depth
```

### DangerDetectionArray.msg

发布者：

```text
a1_danger_perception
```

典型 topic：

```bash
/danger_perception/detections
```

作用：

```text
表示某一帧或某一次同步传感器回调中的多个危险源观测。
```

一帧图像里可能有 0 个、1 个或多个危险源候选，所以需要数组。

订阅者可能包括：

```text
a1_result_manager
a1_mission_manager
调试/可视化工具
```

### DangerSource.msg

发布者：

```text
a1_result_manager
```

作用：

```text
表示经过多帧融合、空间聚类、去重和置信度筛选后的一个真实危险源。
```

它不是单帧检测，而是 result_manager 对多个 `DangerDetection` 的汇总结果。

例如同一个红球被连续观测到 20 次，最终应该融合为一个 `DangerSource`：

```text
source_id
position
confidence
observation_count
class_name
status
```

### DangerSourceArray.msg

发布者：

```text
a1_result_manager
```

典型 topic：

```bash
/a1/result_manager/danger_sources
```

作用：

```text
表示当前所有已确认、候选或被管理中的危险源列表。
```

订阅者可能包括：

```text
a1_mission_manager
UI / 可视化工具
测试脚本
```

它也可以作为最终写 `results/detected_danger.json` 前的结构化中间结果。

### ExplorationStatus.msg

发布者：

```text
a1_exploration
```

典型 topic：

```bash
/a1/exploration/status
```

作用：

```text
表示探索模块当前状态，例如空闲、选择目标、导航中、探索完成、失败或暂停。
```

订阅者通常是：

```text
a1_mission_manager
测试脚本
UI / 日志工具
```

它汇报探索进展，例如当前楼层、覆盖率和当前探索目标。

单层探索返航的状态语义为：

```text
IDLE
→ RECORD_START
→ SELECTING_TARGET（业务状态名 SELECT_FRONTIER）
→ NAVIGATING
→ UPDATE_COVERAGE
→ EXPLORATION_DONE
→ RETURNING
→ RETURNED
```

`FAILED` 表示不可自动恢复的地图、导航、超时或返航错误；`CANCELLED`
表示调用方取消。原有状态数值 `0..5` 保持不变，新状态从 `6` 起追加。

发布契约：

- 发布者：`a1_exploration`；消费者：`a1_mission_manager`、测试、UI/日志。
- topic：`/a1/exploration/status`，进程存活期间以固定频率发布并 latched。
- `header.stamp` 是状态发布时间；`header.frame_id` 是本次探索 OccupancyGrid
  的全局坐标系；没有可用地图时可以为空。
- `current_target` 使用同一全局坐标系，单位为米和四元数；非导航状态允许为空。
- `coverage_ratio` 是当前固定楼层栅格中已知 cell 的比例，只用于进度与回归比较；
  默认探索完成仍以“无合格 frontier / 剩余 frontier 均不可达”为准。
- action 结束后 `RETURNED`、`FAILED` 或 `CANCELLED` 保持到下一目标开始，便于晚到订阅者
  读取结果。

### FloorStatus.msg

发布者：

```text
a1_floor_mapping
```

典型 topic：

```bash
/a1/floor_mapping/floor_status
```

作用：

```text
表示机器人当前所在楼层、楼层高度范围、是否处在楼层切换区域，以及当前楼层二维地图是否可用。
```

订阅者可能包括：

```text
a1_mission_manager
a1_exploration
a1_navigation
a1_bringup
```

注意：真正的二维地图不要在这里自定义，仍然使用标准：

```text
nav_msgs/OccupancyGrid
```

`FloorStatus.msg` 只描述楼层状态，不承载整张地图。

### WallSegment.msg / WallSegmentArray.msg

发布者：

```text
a1_floor_mapping
```

典型 topic：

```bash
/a1/floor_mapping/walls
```

作用：

```text
发布当前 localization generation 与 floor session 中已经跨帧稳定的二维墙段。
```

`detection_id` 只在同一个 `localization_generation + floor_session_id` 内稳定。消费者必须同时检查 floor_mapping 的结构健康状态；数组为空可能表示当前没有稳定墙段，也可能表示结果失效，不能脱离 `structure_status.results_valid` 解读。

### Doorway.msg / DoorwayArray.msg

发布者：

```text
a1_floor_mapping
```

典型 topic：

```bash
/a1/floor_mapping/doorways
```

作用：

```text
发布由共线墙段与穿透自由射线共同证实的墙体开口，及 OPEN、CLOSED、PARTIALLY_OPEN、BLOCKED、UNKNOWN 状态。
```

`Doorway` 首先是感知几何，不是门控授权。`control_id_matched=false` 和空 `control_door_id` 是正常且安全的默认值；后续行为模块只能在独立可靠关联后才调用 `/set_door_state` 或电梯服务。普通房间开口不得仅因宽度接近电梯门而被绑定业务 ID。

### MissionStatus.msg

发布者：

```text
a1_mission_manager
```

典型 topic：

```bash
/a1/mission/status
```

作用：

```text
表示顶层任务状态，例如等待定位、等待地图、探索中、靠近危险源、跨楼层、恢复、完成或错误。
```

订阅者可能包括：

```text
a1_bringup
a1_result_manager
a1_cmd_mux
测试脚本
UI / 日志工具
```

注意：这个消息不是给 `a1_mission_manager` 输入用的，而是由 `a1_mission_manager` 生成并对外发布，用来告诉其它模块“总任务现在在做什么”。

### SearchRegion.msg

发布者：

```text
a1_floor_mapping
```

或在更高层设计中由地图语义模块发布。

作用：

```text
表示一个可搜索区域，例如房间、走廊、门口、电梯区、楼梯区。
```

它包含区域所属楼层、区域 ID、区域类型、边界、多大优先级、是否可达、是否已访问和状态。

如果探索模块只需要普通栅格地图，可以暂时不用这个消息，直接基于 `nav_msgs/OccupancyGrid` 做 frontier exploration。

### SearchRegionArray.msg

发布者：

```text
a1_floor_mapping
```

典型 topic：

```bash
/a1/floor_mapping/search_regions
```

作用：

```text
表示某一层楼的一组可搜索区域。
```

订阅者可能包括：

```text
a1_exploration
a1_mission_manager
```

## srv

`srv` 用于一次性请求和响应。适合“请求切换一个模式，然后马上告诉我是否接受”。

### SetMissionMode.srv

服务端：

```text
a1_mission_manager
```

典型 service：

```bash
/a1/mission/set_mode
```

客户端可能包括：

```text
a1_bringup
测试脚本
UI / 人工调试工具
```

作用：

```text
请求 mission_manager 切换任务模式，例如自动、暂停、恢复、停止或完成。
```

它不是长任务，只是一个简单控制入口。长时间执行的任务应该用 action。

## action

`action` 用于长时间任务。它有目标、执行中反馈和最终结果，适合探索整层楼、通过门、电梯、楼梯等持续过程。

### ExploreFloor.action

Action server：

```text
a1_exploration
```

Action client：

```text
a1_mission_manager
```

典型 action：

```bash
/a1/exploration/explore_floor
```

作用：

```text
请求 exploration 模块探索某一层楼。
```

目标包含：

```text
floor_id
seed_target
target_coverage_ratio
timeout_s
floor_entry_pose
roi_local
```

执行中反馈：

```text
当前状态
探索覆盖率
当前探索目标
消息
```

最终结果：

```text
是否成功
错误码
最终覆盖率
消息
```

注意：单个导航目标仍然使用标准 `move_base_msgs/MoveBaseAction`，不要用这个 action 替代普通导航。

单层探索返航契约补充：

- server：`a1_exploration`；client：`a1_mission_manager` 或验收脚本；
  action 名称保持 `/a1/exploration/explore_floor`。
- `seed_target` 与所有 feedback 位姿均使用 `geometry_msgs/PoseStamped`；当前实现要求非空
  `frame_id` 与当前楼层地图 frame 相同。今天的自动探索不依赖场景硬编码 seed。
- `floor_entry_pose` 使用当前楼层地图 frame，单位米，yaw 的 +X 方向指向室内；
  显式输入的位置必须为有限值，姿态必须是单位二维四元数
  （`abs(x), abs(y) <= 1e-6`，模长误差 `<= 1e-3`）。server 不会把非法
  3D 姿态静默投影到 yaw，而是在门请求和任何 MoveBaseAction 之前以
  `ERROR_INVALID_ENTRY_POSE` 拒绝；
  `roi_local` 是相对该入口的 `geometry_msgs/Polygon`，x 向前、y 向左、单位米。
  二者与 RECORD_START 返航位姿相互独立。生产配置要求显式入口位姿；只有调用方明确将
  `entry/require_explicit_pose=false` 时，空字段才使用兼容入口偏移；
  算法不得从 generated_building、Gazebo model states、裁判真值或固定世界坐标生成它们。
- 本次 action 启动时绑定 `frame_id + localization_generation + floor_session_id`，
  任一项变化都取消正在执行的 MoveBaseAction 并以 `ERROR_MAP_LOST` 失败。
- `timeout_s` 单位秒，使用 ROS 时间；实现另有墙钟 watchdog 防止 `/clock` 冻结。
  `timeout_s=0` 表示无总业务超时，但单个导航和返航仍有独立安全超时。
- 单个 frontier 和返航目标全部调用标准 `/move_base` Action；exploration 不发布
  `/cmd_vel_nav` 或 `/cmd_vel`。
- `success=true` 只表示“探索判据成立、已通过 MoveBaseAction 返回记录起点、位置/航向
  在容差内、最终 `/cmd_vel` 新鲜且持续为零”四项全部满足。
- `error_code` 常量为：
  `ERROR_PRECONDITION`、`ERROR_MAP_LOST`、`ERROR_NAVIGATION_UNAVAILABLE`、
  `ERROR_TIMEOUT`、`ERROR_RETURN_FAILED`、`ERROR_SAFETY_STOP`、
  `ERROR_CANCELLED`、`ERROR_ENTRY_DOOR`、`ERROR_ENTRY_TRANSIT`、
  `ERROR_ENTRY_MAP`、`ERROR_INVALID_ENTRY_POSE` 和 `ERROR_INTERNAL`。
- cancel 或 safety lock 的语义是立即取消当前 MoveBaseAction 并停车，不擅自继续返航；
  调用方可在安全条件恢复后发起新 action。
- `/a1/controller_ready` 必须是新鲜的 true 心跳，server 才能发送任何 frontier 或返航
  MoveBaseAction；控制器未就绪、cancel、safety lock 和外部 PREEMPT/RECALL
  都不得写入永久 unreachable 集合。
- `target_coverage_ratio` 为保留的诊断字段，不再作为完成条件；完成只由有效 ROI 内
  连续地图更新均无可达 frontier 触发。覆盖率分母是 ROI 内的 OccupancyGrid cell 中心数。
- 最终零速分别验证消息新鲜度和“最后一次非零后至少 0.5 ROS/仿真秒”；
  消息过期、非有限值或时钟回退均 fail-closed。
- action 生命周期只覆盖一个 floor identity。多层任务由 mission_manager 逐层调用；
  门、电梯、楼梯仍由 `SpecialBehavior.action` 负责。

兼容策略：Goal/Result/Feedback 的既有字段和原状态数值均不删除、不改名、不改值；
`ERROR_INVALID_ENTRY_POSE=11` 只在既有 0..10 错误码之后追加；
本次在 Goal 尾部追加 `floor_entry_pose` 与 `roi_local`；旧客户端若确需过渡，必须由部署方
显式开启配置 fallback。ROS 消息 MD5 会变化，因此相关包必须在同一工作区重新编译。

### SpecialBehavior.action

Action server：

```text
a1_building_behavior
```

Action client：

```text
a1_mission_manager
```

典型 action：

```bash
/a1/building_behavior/special_behavior
```

作用：

```text
请求 building_behavior 完成门、电梯、楼梯、对准通道等普通二维导航难以直接处理的特殊行为。
```

行为类型包括：

```text
OPEN_DOOR
CALL_ELEVATOR
RIDE_ELEVATOR
PASS_STAIRS
ALIGN_TO_PASSAGE
```

注意：门和电梯的底层服务不要在这里重复定义，应优先复用已有 `building_generator_interfaces` 中的 `/set_door_state`、`/call_elevator` 等接口。

## 发布者和订阅者速查

```text
a1_floor_mapping
  发布 FloorStatus
  可选发布 SearchRegionArray
  发布 WallSegmentArray、DoorwayArray（门洞是感知几何结果，不能据此直接控制门）
  地图仍发布 nav_msgs/OccupancyGrid

a1_danger_perception
  发布 DangerDetectionArray

a1_result_manager
  订阅 DangerDetectionArray
  发布 DangerSourceArray

a1_exploration
  发布 ExplorationStatus
  提供 ExploreFloor.action server

a1_mission_manager
  发布 MissionStatus
  提供 SetMissionMode.srv server
  调用 ExploreFloor.action
  调用 SpecialBehavior.action
  调用 move_base_msgs/MoveBaseAction

a1_navigation
  使用 move_base_msgs/MoveBaseAction
  输出 /cmd_vel_nav，类型 geometry_msgs/Twist

a1_building_behavior
  提供 SpecialBehavior.action server
  输出 /cmd_vel_behavior，类型 geometry_msgs/Twist
  调用 building_generator_interfaces 里的门/电梯服务

a1_cmd_mux
  订阅 /cmd_vel_nav、/cmd_vel_behavior、/cmd_vel_teleop
  发布最终 /cmd_vel
  发布 CmdMuxStatus
```

## 一句话总结

```text
Detection 是感知的一次观测。
Source 是结果管理融合后的真实危险源。
FloorStatus 描述当前楼层。
SearchRegion 描述哪里需要搜索。
ExplorationStatus 描述探索模块状态。
MissionStatus 描述顶层任务状态。
CmdMuxStatus 描述谁在控制最终速度。
SetMissionMode 用于外部切换任务模式。
ExploreFloor 用于请求探索一层楼。
SpecialBehavior 用于请求门、电梯、楼梯等特殊行为。
```
